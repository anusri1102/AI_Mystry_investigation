# AI Mystery Room

An interactive, fictional investigation game. Players create a mystery premise, examine evidence, take notes, accuse one suspect, then receive a verdict. The backend stores the canonical culprit privately and never includes it in active case responses.

## Requirements

- Node.js 20 or newer
- npm 10 or newer
- MongoDB (local or Atlas)
- A Google Gemini API key for case generation

## Setup

1. Configure `server/.env` with `MONGODB_URI`, `GEMINI_API_KEY`, and a random `SESSION_SECRET` (32+ characters). The default text model is `gemini-3.8-flash`; model IDs can be changed through `GEMINI_MODEL`.
2. From the repository root run `npm install`.
3. Run `npm run dev` to start the Express API on port 4000 and Vite on port 5173. Restart the server process after editing backend files.
4. Open `http://localhost:5173`.

Set `CLIENT_ORIGIN` to the deployed frontend origin in production. Set `VITE_API_URL` for a separately hosted API. During development, the API permits both `localhost:5173` and `127.0.0.1:5173`, and the client uses the same hostname as the page for API calls. The API uses an HttpOnly session cookie; keep the frontend and API on the same site in production so SameSite cookie protection works as intended.

## Deploy (Vercel + Render + MongoDB Atlas)

The repository includes `vercel.json` and `render.yaml` for this setup. Vercel serves the Vite client and proxies `/api/v1/*` to Render, so API calls and the session cookie use the same browser origin.

1. Push the repository to GitHub. Confirm `server/.env` is not committed; add the deployment secrets only in Render.
2. Create a MongoDB Atlas cluster and database user. Copy the application's MongoDB connection string for the `MONGODB_URI` environment variable. In Atlas Network Access, allow Render's outbound IP addresses for the service's region. Atlas accepts only connections from addresses in its IP access list.
3. In Render, choose **New + → Blueprint**, connect the GitHub repository, and deploy the Blueprint. It creates the `ai-mystery-room-api` web service. In the service's Environment settings, enter `MONGODB_URI` and `GEMINI_API_KEY`; `SESSION_SECRET` is generated by the Blueprint. Wait for `/health` to report `{"status":"ok","service":"AI Mystery Room API"}`. The Blueprint assumes the Render URL is `https://ai-mystery-room-api.onrender.com`; if Render assigns a different URL, update the API rewrite destination in `vercel.json` to that URL and commit the change.
4. In Vercel, import the same GitHub repository. Keep the **Root Directory** at `./` (repository root); the build and output settings are in `vercel.json`. Deploy the project.
5. Copy the production domain assigned by Vercel. In Render's Environment settings, set `CLIENT_ORIGIN` to that exact origin, such as `https://your-project.vercel.app` (no trailing slash), then save and redeploy the API.
6. Redeploy Vercel if you changed `vercel.json`. Open the Vercel URL, create a case, and check that `/health` works on the Render URL and the app can create a case.

For later updates, push commits to the connected GitHub branch; Vercel and Render will deploy from that branch. Do not put `GEMINI_API_KEY`, `MONGODB_URI`, or `SESSION_SECRET` in Vercel client environment variables or commit them to Git. The free Render web service may sleep while idle, so its first request after inactivity can take longer.

Image and video generation are separate provider adapters. They are unconfigured by default. Image evidence is explicitly labeled as an illustrative textual reconstruction; CCTV entries are displayed as text evidence when video is unavailable. No still is described as a recording. Set `IMAGE_PROVIDER` and `VIDEO_PROVIDER` only when corresponding adapters are implemented and configured.

## MVP flow

Landing page → case intake → asynchronous Gemini generation → investigation dashboard → evidence review / notes → one final accusation → verdict. Guest case ownership is tied to a Mongo-backed, HttpOnly session cookie. Case generation is rate limited. Authentication, user profiles and history across devices are follow-up scope; the current archive is session-scoped.

## Scripts

- `npm run dev` — start frontend and backend in parallel
- `npm run dev:client` — frontend only
- `npm run dev:server` — backend only
- `npm run build` — create the Vite production bundle
- `npm start` — start the API
